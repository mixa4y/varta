# VARTA workspace rules

## Canonical repository

- Єдиний робочий репозиторій: `D:\VARTA`.
- Два вихідні каталоги CaseFlow і CMSD поза цим репозиторієм є read-only
  джерелами міграції.
- Нові зміни не вносяться безпосередньо у старі каталоги.

## Privacy boundary

- За прямим дозволом користувача від 2026-09-13 корпус
  `workspaces/materialy-spravy/corpus/` та його опис/маніфест дозволено
  комітити й публікувати у відкритому репозиторії VARTA, включно з реальними
  документами справи та їхніми підписами. Це явний виняток для цього корпусу.
- Інші матеріали справ і generated case maps не публікувати без окремого
  дозволу. OAuth-токени, паролі, приватні ключі та DPAPI blobs не комітити.
- Агенти мають прямий доступ до цього корпусу; локальна програма використовує
  `workspaces/materialy-spravy/settings.json` та workspace `runtime/` поруч.
  SQLite, локальні налаштування та runtime-артефакти залишаються поза Git.
- Приклади мають бути порожніми або явно вигаданими та не відтворювати
  реальні ПІБ, номери справ, суми чи шляхи користувача.
- Перед push запускати пошук case-specific значень і перевіряти staged diff.

## Product boundary

- Універсальний код не містить номера конкретної справи або фіксованого
  списку проваджень.
- Case-specific дані зберігаються у versioned case profile поза core.
- Оригінали незмінні; generated artifacts відтворювані; SQLite та файлове
  сховище є джерелом істини.
- Людиночитні керовані імена використовують українські терміни транслітом
  за КМУ №55, а не англійський переклад.

## Verification

- Зміни коду супроводжуються тестами.
- Не приховувати помилки або невизначеність.
- Не видаляти й не переміщувати матеріали справ під час тестування.
