## Призначення

Описати тестові пакети без реальних персональних даних. Наведені назви й реквізити є синтетичними та не відтворюють конкретну справу.

## Package A: `basic_intake`

```text
basic_intake/
├── submission.pdf
├── attachment_01.pdf
└── cover_letter.docx
```

Очікування: три оригінали, три SHA-256, один `import_batch`, без зміни джерел. Зв'язки між документами не визначаються автоматично без достатніх сигналів.

## Package B: `duplicate_and_version`

```text
duplicate_and_version/
├── document_original.pdf
├── document_copy.pdf
└── document_revised.pdf
```

`document_copy.pdf` має бути побітовою копією першого файла. `document_revised.pdf` містить синтетичну зміну одного абзацу. Очікування: `exact_match` для копії та `possible_version` або `content_difference` для редакції залежно від затверджених правил.

## Package C: `attachments_mismatch`

Основний синтетичний документ заявляє два додатки; пакет містить один заявлений і один незаявлений файл. Очікування: `declared_but_missing`, `declared_and_present`, `present_but_undeclared`.

## Package D: `signature_cases`

Містить лише спеціально створені тестові сертифікати та документи: валідний підпис, змінений вміст, відокремлений підпис без data file, непідтримуваний контейнер. Жоден реальний приватний ключ не включається.

## Package E: `unicode_and_paths`

Назви містять українські літери, пробіли, дужки й довгий вкладений шлях. Заборонені Windows-символи не генеруються. Очікування: коректний імпорт і збереження оригінальних назв.

## Правила знеособлення

- Використовувати синтетичні ПІБ, адреси, номери, підписи та дати.
- Не замінювати лише ім'я в реальному документі, якщо інші реквізити можуть ідентифікувати особу.
- Зберігати окремий опис того, які властивості тесту навмисно відтворені.
- Перевіряти fixtures на випадкові персональні дані перед включенням у репозиторій.
