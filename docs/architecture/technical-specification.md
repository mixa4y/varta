## Мета

Створити універсальний локальний застосунок для керованого приймання, збереження, аналізу та порівняння матеріалів судових справ.

## Scope

- Імпорт окремих файлів, каталогів і підтримуваних архівів.
- Створення `import_batch` та реєстру отриманих файлів.
- Обчислення SHA-256 під час приймання.
- Збереження незмінної копії оригіналу.
- Фіксація походження, шляхів, розміру, типу та часових атрибутів.
- Виявлення дублів за хешем без автоматичного видалення.
- Класифікація документів із рівнем упевненості.
- Зіставлення документів на кількох рівнях.
- Перевірка заявлених і фактичних додатків.
- Збереження результатів перевірки КЕП.
- Формування хронології, findings, audit log і звітів.

## Out of scope для v0.1

- Автоматична юридична кваліфікація доказів.
- Автоматичне твердження про фальсифікацію.
- Багатокористувацький хмарний сервіс.
- Обов'язкова інтеграція з Airtable.
- Передавання приватних ключів зовнішнім сервісам.

## Функціональні вимоги

### Intake

Система створює ідентифікатор імпорту, реєструє джерело та кожен виявлений файл. Помилка одного файла не повинна приховувати результати інших; статус і причина фіксуються.

### Storage

Оригінал копіюється в кероване сховище без зміни байтів. Робочі та похідні файли зберігаються окремо. Заміна наявного оригіналу за тим самим шляхом заборонена.

### Integrity

Для кожного оригіналу обчислюється SHA-256. Повторна перевірка має повідомляти `verified`, `mismatch` або `error`, не змінюючи файл.

### Processing

Кожна суттєва операція створює `processing_run` із типом, параметрами, версією інструмента, часом, статусом і помилкою. Похідні результати посилаються на вхідні файли.

### Review

Невизначені або конфліктні результати отримують `manual_review_required`. Система зберігає автоматичний висновок окремо від рішення користувача.

## Нефункціональні вимоги

- Підтримка Windows, Unicode, кирилиці й довгих шляхів.
- Транзакційність змін структурованих даних.
- Відтворюваність і структуроване журналювання.
- Міграції схеми без прихованого видалення даних.
- Доменно незалежна логіка без hardcode конкретної справи.
- Type hints і модульні тести для Python-коду.

## Інтерфейси

Core не повинен залежати від конкретного UI. Операції мають бути доступні через application services; CLI або local UI викликають ті самі контракти.

## Критерії приймання v0.1

- Імпорт тестового пакета не змінює джерело.
- Усі імпортовані файли мають SHA-256 і provenance.
- Повторний імпорт ідентичного файла фіксується як потенційний дубль.
- Після перезапуску дані читаються із SQLite.
- Звіт інвентаризації відтворюється з БД.
- Помилки доступні користувачу й у журналі.
